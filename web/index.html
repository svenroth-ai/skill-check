Shipwright Skill Check

A local app that reads your skills, shows what each one really does, and turns the gaps into a hardening plan you approve step by step.

All skills, numbers and results on this page are made-up examples. Nothing is read from a real machine, and nothing is sent anywhere. The data format (sections with anchors and hashes, classes, targets, truth table, subprocess map) and the limits follow the Shipwright changelog pilot and shared/config/conventions.json. README, not part of the app

Install and start

Two lines. The app starts after the second one and opens with the explanation below.

$ npx @svenroth-ai/skill-check  # once: adds the plugin to Claude Code
> /skill-check  # in Claude Code: starts the app beside the chat
http://localhost:3920 Runs locally. Nothing leaves this machine unless you share a report.
Why this exists

A skill should do what you wrote, every time

Most skills are instructions in plain text. Claude reads them and usually follows them, but nothing makes it. This tool shows you where that is a risk and how to close it.

It does what you decided

A rule written in text is a request. A rule run as a check is a fact. The check shows which of your rules are which.

No shortcuts

Under time pressure a model can skip a step or shorten it. A check in code cannot be skipped.

Predictable results

The same input should give the same behavior. A recorded baseline of what the skill does today lets you prove that a change did not alter it.

In line with Anthropic's guidance

Anthropic's skill authoring guidance recommends scripts for steps that must be exact, and text only where judgment is needed. This tool measures your skills against that.

Scripts first

Parsing, token counts, trigger overlap and rule classification run as plain scripts. A model only words the requirements and settles unclear cases.

Everything stays local

Results are saved as JSON files in a data folder on your machine. You can open them without the app.

You approve each change

The app proposes. Every hardening step needs your click before anything is rebuilt.

Same files as Shipwright

The three data files use the format of the Shipwright skill rebuilds, so a Shipwright run can start from them without conversion. Without Shipwright they are still readable JSON.

Derived requirements

Stated means it is written in the skill. Inferred means it was concluded from scripts and behavior, so you confirm it.

AC: any write to contracts/ is blocked and reported.

Step 5 · with Shipwright

Rebuild and proof
